# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Converts a boat's lines plan "table of offsets" (CSV, values in feet-inches-eighths such as `1-10-2`) into DXF drawings using `ezdxf`. Units are inches. Core library is the single module `table_of_offsets.py`; per-project scripts live in `tutorial/`.

## Commands

    python3 -m venv ~/.venvs/off2dxf && source ~/.venvs/off2dxf/bin/activate
    pip3 install -r requirements.txt        # numpy, pandas, ezdxf, black

    python -m unittest discover -v -s ./tests -p "test_*.py"     # all tests (same args as .vscode/settings.json)
    python -m unittest discover -s ./tests -p "test_*.py" -k offset2double   # single test by name

    black .                                  # formatter (format-on-save in VS Code)

Tutorial scripts (e.g. `tutorial/project89.py`) are run directly and write `.dxf` files into `./out` in the current directory (git-ignored; `--out-dir DIR` to change, see `table_of_offsets.output_dir_from_args`; `DXF.close` creates the directory). The coordinates in the .dxf are in `Model.output_unit()` (default the unit of the table, "inch" for `ftin`; `--output-units` / `set_output_unit`); `Model.open_dxf(file)` makes a `DXF(file, unit=...)` that scales the inch coordinates and the text heights and sets `$INSUNITS`.

## Architecture

- `TableOfOffsets.offset2double` parses `F-I-E` strings to inches. Trailing `+`/`-` means +/- 1/16". Missing parts are allowed (`1-0`, `3`). A cell with two values (`0-2-0 and 0-3-0`) is malformed unless `Model.set_multi_value_policy("first")` (see `MULTI_VALUE_POLICIES`) is set: then the first value is used; project 89 sets it.
- `Model` wraps a pandas DataFrame read from the CSV (cells kept as text; `Model(csv, unit=...)` with `unit` one of `TableOfOffsets.UNITS` - default `"ftin"`, or e.g. `"mm"` - converts them to inches via `offset_to_inches`). First column `#` is the line name (Sheer, `B 3'`, ...); other columns are station numbers. Station x-position is `(33 - station) * 12` (hard-coded for the 33-station sample layout). It is a base class: subclasses override the "(virtual)" methods (`waterlines_positions`, `buttocks_positions`, `base_offset`, `grid_y_origins`, `drawing_area_vertical_borders`, `breadth_line_to_index`, `height_line_to_index`). `set_under_waterline` marks stations where a line's offsets are negated (see `offset_sign`).
- `DXF` is a context manager around an `ezdxf` R2010 doc with layers `grid`, `red`, `text`. It saves on exit. Note that `__exit__` re-raises as a bare `Exception` and returns True.
- `tutorial/projectNN.py` / `projectbluemoon.py` each subclass `Model` for one boat's CSV, then plot the grid and lofted lines. `tutorial/context.py` and `tests/context.py` put the repo root on `sys.path` so `import table_of_offsets` works; scripts and tests import via `from context import ...`.

## Body plan

`loft_body_line(station, [(breadth, height), ...])` builds one body line; each item is a table row name or a number in inches. `breadth_at` / `height_at` look rows up by name (`breadth_line_to_index` / `height_line_to_index` are overridable). `breadth_at` ignores `base_offset` (sheet placement is vertical only). `ProjectBlueMoon.body_lines()` is the reference example; Options: `placement` (`"max_breadth"` default = centerline on the widest station, `"right"` = clear of the profile view, `"raw"`) and `sides` (`"half"`, `"both"`, `"split"` = aft stations left, forward right; default `"split"` for `"max_breadth"`, `"half"` otherwise, see `body_plan_sides`; the bow end comes from `set_bow_station(station)` / the `bow_station` argument, default the greater x). Both projects now produce body lines. Diagonals: the overridable `diagonals_positions()` gives `{name: (y0, x1, y1)}` (inches, heights above the base line; the line from `(0, y0)` through `(x1, y1)`), the table row (`diagonal_row(name)`, default the name) holds the distance along it from `(0, y0)` to the hull. `loft_body_lines` adds the hull points of the diagonals that are in the table (`diagonal_body_points()`, `DiagonalPoint` items of `body_points`) like the waterlines, and the diagonals are drawn in the grid (`diagonal_segments`). In the plan view the diagonals are drawn below the plan centerline, opposite to the waterlines and the sheer (`loft_diagonal_plan_lines`, `plot_diagonal_plan_lines`, used by `ProjectTabbyCat.save_model_as`). The definitions are data that must be given (read from the drawing or provided), not guessed or fitted: the Tabby Cat model has them from the dimensions of `konstruktivnyy_midel-shpangout_2.jpg` (`DIAGONALS_MM`). The lowest point of every body line (the keel) is joined to the centerline by a horizontal segment (`keel_link=True`, `loft_body_lines`). The first of the `body_points` is the sheer: `loft_body_lines` returns a `BodyLines` (a dict with the attribute `sheer`, see `body_sheer_polylines(lines)`) whose sheer line joins the sheer points of the consecutive stations, one polyline per side; stations whose sheer cell is empty are skipped, not extrapolated (see the TODO). The rabbet line (`BodyLines.rabbet`, `body_rabbet_polylines`) is made the same way from the point of the overridable `rabbet_body_point()` (default `None` = no rabbet line; the Tabby Cat, Blue Moon and project 89 models override it; the ferrocement hull has no rabbet). The keel line (`BodyLines.keel`, `body_keel_polylines`, `keel_body_point()`; all four projects override it, project 89 uses `Profile Plan`/`Profile`) is a separate thing from the keel link (the lowest point joined to the centerline). With `placement="right"`, `body_plan_grid_options()` gives `plot_grid` the extension of the base line (first `grid_y_origins`) and waterlines plus a vertical body plan centerline and the buttock lines (`buttocks_positions`). `loft_body_lines` always adds the waterlines of `waterlines_positions()` that have a half-breadth row in the table (`waterline_body_points()`, row name from the overridable `waterline_row(name)`), so projects list only the other points; it returns `{station: [polyline, ...]}`; `body_polylines()` flattens it. `plot_annotated_body_line(dxf, station, body_points)` (used by `ProjectFerrocement.save_station_as`) draws one station with every point labelled with the table rows its coordinates come from, plus the base line (y = 0), the waterlines and the buttocks, for checking odd body lines. `plot_body_lines(dxf, lines)` draws them with the station name above the top end of each, and the sheer, rabbet and keel lines (`sheer=False`, `rabbet=False`, `keel=False` to omit; the tutorial scripts use it). `plot_body_plan_grid(dxf, lines)` draws the grid (base line, waterlines, `CL`, buttocks) of a body plan alone; the `save_body_lines_as` methods (the `*_body.dxf` files) draw it under the body lines.

  - the transcription of `sample_data/a_ferrocement_hull/offset_table.csv` has not been checked against the GIF (e.g. `Breadth WL 3` at station 3 is 774 after 124 at station 2);
  - assumed layout: stations 1000 mm apart, `T` at x = 0, buttocks 500 mm apart;
  - the waterline heights are not in the table; they are derived from the draught (1800 mm = DWL = WL 5) and the 250 mm spacing (WL 1 = 800 ... WL 8 = 2550). The body lines include the waterline points; they make the sections zigzag because they do not agree with the buttock heights (e.g. station 6: WL 1 at 800 mm has a breadth of 161 mm but Buttock III, 1500 mm out, is only 820 mm high). The draught and the spacing come from the lines plan, whose characteristics (B = 4.28 m, depth 1.99 m) do not match the offsets table (deck half-breadth 1562 mm, sheer up to 2985 mm), so the two images may show different hulls;
  - the diagonals (Height Diagonal A-C) are not used: they are heights, not distances along a diagonal line, and the diagonal lines are not known (see `diagonals_positions`).

## Data

`sample_data/` holds the primary CSV and `a_ferrocement_hull/` (a table in millimetres transcribed from an FAO drawing, with the source images; see `tutorial/project_ferrocement.py`) and `tabby_cat/` (a table in millimetres transcribed from a lines plan picture; waterline heights given by the user, buttocks 300 mm and stations 510 mm apart, confirmed by the user; see `tutorial/project_tabby_cat.py`). `sample_data_too/` is a git submodule (`git@github.com:yyk99/tables_of_offsets.git`) with more tables (`offset_table_181.csv`, `offset_table_blue_moon.csv`). Run `git submodule update --init` to fetch it.
